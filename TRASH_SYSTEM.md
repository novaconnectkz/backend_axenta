# Система корзины удаленных элементов

## Описание

Система корзины обеспечивает безопасное удаление элементов с возможностью восстановления. Все удаленные элементы хранятся в отдельной таблице `deleted_items` с полной детализацией: кто, когда и что удалил.

## Возможности

- ✅ Soft delete - элементы не удаляются физически из базы данных
- ✅ Полный аудит удалений (кто, когда, что)
- ✅ Восстановление удаленных элементов
- ✅ Окончательное удаление (для полной очистки)
- ✅ Фильтрация и поиск по удаленным элементам
- ✅ Статистика корзины
- ✅ Изоляция по company_id (мультитенантность)

## Архитектура

### Backend

#### Модели

1. **DeletedItem** (`models/deleted_item.go`)
   - Хранит информацию об удаленных элементах
   - Поля:
     - `entity_type` - тип элемента (user, contract, object, etc.)
     - `entity_id` - ID удаленного элемента
     - `entity_data` - JSON с данными элемента
     - `deleted_by` - ID пользователя, который удалил
     - `deleted_by_name` - имя пользователя
     - `deleted_at_custom` - дата удаления
     - `company_id` - ID компании (для изоляции)
     - Флаги восстановления и окончательного удаления

#### API Endpoints

**GET `/api/trash/items`** - Получить список удаленных элементов
- Параметры:
  - `entity_type` - фильтр по типу
  - `search` - поиск по названию/описанию
  - `show_restored` - показать восстановленные
  - `show_permanently_deleted` - показать удаленные навсегда
  - `page`, `limit` - пагинация

**GET `/api/trash/stats`** - Получить статистику корзины

**POST `/api/trash/items/:id/restore`** - Восстановить элемент
- Body: `{ "restore_note": "причина восстановления" }` (опционально)

**DELETE `/api/trash/items/:id/permanent`** - Окончательно удалить элемент

#### Helper функция

`RecordDeletion()` в `api/trash.go` - записывает информацию об удалении в таблицу `deleted_items`

Пример использования:
```go
// При удалении пользователя
api.RecordDeletion(
    db,
    "user",           // тип сущности
    user.ID,          // ID элемента
    user,             // данные элемента
    deletedBy,        // ID пользователя, который удаляет
    deletedByName,    // имя пользователя
    companyID,        // ID компании
    user.Username,    // название для отображения
    user.Email,       // описание
)
```

### Frontend

#### Компоненты

**Trash.vue** (`components/Settings/Trash.vue`)
- Главный компонент для работы с корзиной
- Функции:
  - Просмотр списка удаленных элементов
  - Фильтрация по типу и поиск
  - Просмотр деталей удаленного элемента
  - Восстановление элементов
  - Окончательное удаление
  - Массовые операции

#### Сервисы

**trashService.ts** (`services/trashService.ts`)
- `getTrashItems()` - получить список
- `getTrashStats()` - получить статистику
- `restoreItem()` - восстановить элемент
- `permanentlyDeleteItem()` - окончательно удалить
- `restoreMultipleItems()` - массовое восстановление
- `permanentlyDeleteMultipleItems()` - массовое удаление

#### Типы

**trash.ts** (`types/trash.ts`)
- `DeletedItem` - интерфейс удаленного элемента
- `TrashStats` - статистика корзины
- `EntityType` - типы сущностей
- `EntityTypeLabels`, `EntityTypeIcons`, `EntityTypeColors` - метаданные для отображения

## Использование

### Настройка страницы Settings

Корзина добавлена как отдельная вкладка в `/settings`:

1. Импортирован компонент `Trash.vue`
2. Добавлена вкладка "Корзина" в список вкладок
3. Добавлена загрузка статистики корзины для отображения бейджа

### Интеграция в существующий код

Для интеграции системы корзины в существующие endpoints удаления:

1. Перед вызовом `db.Delete()` получите данные элемента
2. Вызовите `api.RecordDeletion()` для записи в корзину
3. Выполните `db.Delete()` (soft delete)

Пример:
```go
// Получаем элемент
var user models.User
db.First(&user, userID)

// Записываем в корзину
api.RecordDeletion(
    db,
    "user",
    user.ID,
    user,
    currentUserID,
    currentUserName,
    companyID,
    user.Username,
    user.Email,
)

// Удаляем (soft delete)
db.Delete(&user)
```

## Безопасность

- ✅ Все операции требуют аутентификации
- ✅ Изоляция данных по `company_id`
- ✅ Пользователи видят только удаленные элементы своей компании
- ✅ Аудит всех операций восстановления и окончательного удаления

## Миграция

Таблица `deleted_items` создается автоматически при запуске миграций:

```bash
go run cmd/server/main.go
```

Миграция зарегистрирована в `database/migrations.go`:

```go
{
    TableName:   "deleted_items",
    Model:       &models.DeletedItem{},
    Description: "Корзина удаленных элементов (аудит удалений)",
    IsGlobal:    false,
}
```

## UI/UX особенности

### Статистика
- Общее количество элементов в корзине
- Количество доступных для восстановления
- Количество восстановленных элементов
- Количество типов элементов

### Фильтры
- Поиск по названию и описанию
- Фильтрация по типу элемента
- Показ/скрытие восстановленных элементов
- Показ/скрытие окончательно удаленных элементов
- Настройка количества элементов на странице

### Визуализация
- Цветовые метки для разных типов элементов
- Иконки для быстрой идентификации
- Статусы элементов (в корзине, восстановлено, удалено навсегда)
- Относительное время удаления ("2 часа назад")
- Аватары пользователей, которые удалили элементы

### Действия
- Просмотр полных деталей элемента
- Восстановление с подтверждением
- Окончательное удаление с предупреждением
- Массовые операции (выбор нескольких элементов)

## Рекомендации

1. **Регулярная очистка**: Настройте автоматическую очистку старых элементов (например, удаленных более 90 дней назад)
2. **Мониторинг**: Отслеживайте размер таблицы `deleted_items`
3. **Резервное копирование**: Перед окончательным удалением создавайте резервные копии
4. **Права доступа**: Ограничьте окончательное удаление только для администраторов
