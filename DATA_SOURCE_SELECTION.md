# Выбор источника данных для расчета биллинга

## Проблема

Ранее расчет биллинга всегда делался через запросы к Axenta Cloud API, что:
- Медленно (множественные HTTP запросы)
- Нагружает внешний API
- Требует стабильного интернет-соединения

## Решение

Теперь можно выбирать источник данных:
- **Из БД** (быстро) - использует уже сохраненные данные из `axenta_object_snapshots`
- **Из Axenta API** (медленно) - запрашивает актуальные данные из внешнего API

## Как это работает

### В UI (диалог создания партнёрских снимков):

1. Откройте диалог "Создать партнёрские снимки за период"
2. Выберите источник данных:
   - **Из БД** (по умолчанию) - быстро, использует сохраненные данные
   - **Из Axenta API** - медленно, запрашивает актуальные данные
3. Укажите период и нажмите "Создать для всех партнёров"

### Автоматический выбор источника:

- **Автоматический расчет после синхронизации** - всегда использует БД (`data_source=db`)
- **Ежедневный scheduler** - пытается использовать БД, fallback на API при ошибке
- **Ручной запуск через UI** - пользователь выбирает источник

## Технические детали

### Backend API:

```json
POST /api/auth/snapshot-jobs/trigger
{
  "mode": "partner_all",
  "date_from": "2025-12-01",
  "date_to": "2025-12-06",
  "data_source": "db"  // или "api"
}
```

### Логика выбора:

1. Если `data_source=db`:
   - Используется функция `CountPartnerObjectsFromDB()`
   - Подсчет объектов из таблицы `axenta_object_snapshots`
   - Рекурсивный поиск всех дочерних аккаунтов партнера
   - Фильтрация по дате создания/удаления объектов

2. Если `data_source=api`:
   - Используется функция `getPartnerObjectsWithCountForDate()`
   - Запросы к Axenta Cloud API
   - Сохранение объектов в БД после получения

3. Fallback:
   - Если БД недоступна или данных нет, автоматически переключается на API

## Преимущества использования БД:

✅ **Скорость** - в 10-100 раз быстрее (нет HTTP запросов)
✅ **Надежность** - не зависит от внешнего API
✅ **Меньше нагрузка** - не нагружает Axenta Cloud API
✅ **Исторические данные** - можно рассчитывать за любые даты, даже если API недоступен

## Когда использовать API:

⚠️ **Только если:**
- Нужны самые актуальные данные (объекты могли измениться после последней синхронизации)
- Данных нет в БД (первый запуск)
- БД содержит устаревшие данные

## Рекомендации:

- **По умолчанию**: используйте БД (`data_source=db`)
- **Для актуальных данных**: используйте API только при необходимости
- **Автоматические процессы**: всегда используют БД для скорости
