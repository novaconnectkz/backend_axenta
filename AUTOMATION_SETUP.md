# Настройка автоматизации процессов

## Что уже настроено автоматически

✅ **Ежедневные снимки партнеров** - запускаются каждый день в **00:30 UTC (03:30 MSK)**
- Создаются снимки для всех активных партнерских договоров
- Автоматически сохраняются объекты в БД
- После завершения автоматически создаются **billing snapshots**

✅ **Billing snapshots** - создаются автоматически после партнерских снимков
- Используют уже сохраненные данные (без дополнительных запросов к API)
- Обновляют агрегированные показатели в таблице `billing_daily_snapshots`

## Что нужно сделать для включения автоматизации

### 1. Установить переменную окружения

Выполните скрипт:
```bash
./setup_automation.sh
```

Или вручную добавьте в `.env` или `.env.production`:
```bash
ENABLE_SNAPSHOT_SCHEDULER=true
```

### 2. Убедиться, что установлен токен для Axenta API

```bash
AXENTA_ADMIN_TOKEN=ваш_токен_здесь
```

### 3. Перезапустить backend

```bash
# Если используете systemd
systemctl restart backend_axenta

# Если используете PM2
pm2 restart backend_axenta

# Или просто перезапустите приложение
```

## Расписание автоматического выполнения

| Процесс | Время выполнения | Описание |
|---------|------------------|----------|
| Партнерские снимки | 00:30 UTC (03:30 MSK) | Ежедневно, автоматически обрабатывает недостающие даты |
| Billing snapshots | Сразу после партнерских | Автоматически, обрабатывает недостающие даты |
| Синхронизация аккаунтов | Отключена | Можно включить в `main.go` |

### Автоматическая обработка недостающих дат (Catch-up)

**Партнерские снимки:**
- Каждый день в 00:30 UTC система автоматически:
  1. Находит последнюю дату, для которой есть снимки
  2. Создает снимки за все пропущенные дни от последней даты до вчерашнего дня
  3. Если снимков нет вообще, начинает с 2024-03-14

**Billing snapshots:**
- Автоматически обрабатывает недостающие даты:
  1. Находит последнюю дату в `billing_daily_snapshots`
  2. Создает снимки за все дни от последней даты до сегодня
  3. Использует уже сохраненные данные (без дополнительных запросов к API)

## Опционально: Включить автоматическую синхронизацию аккаунтов

Если хотите, чтобы аккаунты синхронизировались автоматически каждую минуту:

1. Откройте `main.go`
2. Найдите строки 116-121 (закомментированный код)
3. Раскомментируйте:
```go
if err := axentaSyncScheduler.Start(); err != nil {
    log.Printf("⚠️ Axenta Sync Scheduler failed to start: %v", err)
} else {
    services.SetAxentaSyncScheduler(axentaSyncScheduler)
    defer axentaSyncScheduler.Stop()
}
```

**Примечание:** Синхронизация не обязательна, так как scheduler использует уже синхронизированные данные или синхронизирует их самостоятельно при создании снимков.

## Проверка работы

После перезапуска backend проверьте логи:

```bash
# Должна появиться строка:
✅ Partner Snapshot Scheduler started (daily at 00:30 UTC / 03:30 MSK)
```

## Ручной запуск (для тестирования)

Если нужно запустить процессы вручную:

### Партнерские снимки за период:
```bash
POST /api/auth/snapshot-jobs/trigger
{
  "mode": "partner_all",
  "date_from": "2025-12-01",
  "date_to": "2025-12-07"
}
```

### Billing snapshots:
```bash
POST /api/auth/billing-snapshots/run-daily
```

### Синхронизация аккаунтов:
```bash
POST /api/auth/axenta-sync/trigger
```

## Мониторинг

История выполнения задач сохраняется в таблице `snapshot_jobs`:
- `job_type = 'daily_auto'` - автоматические ежедневные задачи
- `job_type = 'billing_start'` - пересчет billing snapshots
- `job_type = 'manual'` - ручные запуски

Проверить можно через UI на странице "История автоматических снимков" или через SQL:
```sql
SELECT * FROM snapshot_jobs 
WHERE job_type = 'daily_auto' 
ORDER BY created_at DESC 
LIMIT 10;
```
