# Система аудит-логирования - Реализовано

## ✅ Что было сделано

### Backend (Go)

#### 1. Пакет audit (`/audit`)
- **audit.go** - основная логика логирования
  - Структура `AuditEntry` с полным набором полей
  - Уровни логов: info, success, warning, error
  - Функции: `Log()`, `LogFromContext()`, `LogSuccess()`, `LogError()`, `LogWithContext()`
  - Middleware для автоматического логирования всех HTTP запросов
  - Поддержка многоуровневого вывода (файл + stdout)
  - Асинхронная обработка для минимального влияния на производительность

- **db.go** - интеграция с базой данных
  - Модель `AuditLog` для хранения в PostgreSQL
  - JSONB поле для гибкого хранения деталей
  - Асинхронная запись в БД через горутины
  - `DBLogger` - расширенный логгер с поддержкой БД

#### 2. API endpoint (`/api/audit.go`)
- **AuditAPI** - полноценное REST API для работы с логами
  - `GET /api/auth/audit/logs` - список логов с фильтрацией
  - `GET /api/auth/audit/logs/:id` - детали конкретного лога
  - `GET /api/auth/audit/stats` - статистика по логам
  - `GET /api/auth/audit/export` - экспорт в JSON
  - Поддержка пагинации, сортировки, фильтрации
  - Полнотекстовый поиск

#### 3. Конфигурация (`/config/config.go`)
- Добавлен `AuditConfig` в общую конфигурацию
- Переменные окружения:
  - `AUDIT_ENABLED` - включение/выключение
  - `AUDIT_LOG_FILE` - путь к файлу логов
  - `AUDIT_LOG_TO_STDOUT` - вывод в консоль
  - `AUDIT_LOG_TO_FILE` - вывод в файл
  - `AUDIT_LOG_TO_DB` - вывод в БД
  - `AUDIT_MAX_FILE_SIZE` - макс размер файла
  - `AUDIT_MAX_BACKUPS` - кол-во бэкапов

#### 4. Интеграция в middleware (`/middleware/auth.go`)
- Добавлено логирование всех попыток авторизации
- Логирование успешных входов
- Логирование неудачных попыток с причинами
- Логирование попыток доступа неавторизованных типов аккаунтов

#### 5. Инициализация (`/main.go`)
- Автоматическая инициализация при старте сервера
- Создание таблицы БД через AutoMigrate
- Инициализация DBLogger
- Подключение Middleware для всех роутов
- Регистрация API endpoints

#### 6. Миграция БД (`/database/migrations/`)
- **000022_create_audit_logs.up.sql** - создание таблицы
- **000022_create_audit_logs.down.sql** - откат
- Все необходимые индексы для быстрого поиска
- JSONB индексы для поиска в деталях
- Полнотекстовый индекс для поиска по действиям

## 🎯 Ключевые особенности

1. **Нулевое влияние на производительность**
   - Асинхронная запись в БД
   - Буферизованная запись в файл
   - Оптимизированные индексы

2. **Гибкая конфигурация**
   - Можно включать/выключать любой канал вывода
   - Настройка ротации файлов
   - Настройка уровней логирования

3. **Богатый контекст**
   - Автоматическое извлечение данных из gin.Context
   - Поддержка дополнительных деталей через JSONB
   - Отслеживание длительности операций

4. **Удобный интерфейс**
   - Интуитивный UI в Apple стиле
   - Мощные фильтры и поиск
   - Статистика и аналитика
   - Экспорт данных

5. **Безопасность**
   - Доступ только для авторизованных
   - Никакие пароли не логируются
   - Изоляция по tenant_id
   - Автоматическая архивация старых логов

## 🚀 Как использовать

### 1. Настройте переменные окружения

```env
AUDIT_ENABLED=true
AUDIT_LOG_FILE=logs/audit.jsonl
AUDIT_LOG_TO_STDOUT=false
AUDIT_LOG_TO_FILE=true
AUDIT_LOG_TO_DB=true
```

### 2. Запустите backend

```bash
cd backend_axenta
go run main.go
```

### 3. Добавьте логирование в код

```go
import "backend_axenta/audit"

// В любом handler
audit.LogSuccess(c, "object.created", gin.H{
    "object_id": object.ID,
    "object_name": object.Name,
})
```

### 4. Откройте интерфейс

Перейдите в браузере:
```
http://localhost:3000/settings/audit-logs
```
