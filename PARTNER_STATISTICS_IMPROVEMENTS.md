# Улучшения статистики партнерских договоров

## Описание изменений

Добавлена возможность запрашивать статистику партнерских договоров за любой прошедший период с учетом дат создания, активации и деактивации объектов.

## Основные изменения

### Backend

1. **Новый API endpoint** (`api/partner_snapshots.go`):
   - `POST /api/auth/contracts/:id/partner-snapshots/generate` - создание снимков за указанный период
   - Принимает параметры: `start_date`, `end_date` (формат YYYY-MM-DD)
   - Создает ежедневные снимки для всех дней в указанном периоде

2. **Улучшенная логика подсчета объектов** (`services/partner_snapshot_service.go`):
   - Новая функция `getPartnerObjectsCountForDate()` - подсчитывает объекты на конкретную дату
   - Учитывает дату создания объектов (`CreatedAt`)
   - Учитывает дату удаления объектов (`DeletedAt`)
   - Фильтрует объекты: учитываются только те, что существовали на дату снимка
   - Поддержка множества форматов дат из Axenta Cloud API

3. **Обновление существующих снимков**:
   - При создании снимка на дату, для которой уже есть снимок, происходит обновление данных
   - Это позволяет пересчитывать статистику при необходимости

### Frontend

1. **Улучшенный UI** (`components/Billing/ContractsTab.vue`):
   - Добавлены date pickers для выбора периода статистики
   - Кнопка "Применить" для загрузки статистики за выбранный период
   - Кнопка "Создать снимки" для генерации снимков за период, если их нет

2. **Новые функции**:
   - `loadPartnerStatistics()` - загружает статистику за выбранный период
   - `generateSnapshotsForPeriod()` - создает снимки за выбранный период
   - Автоматическая установка периода по умолчанию (от даты начала договора до сегодня)

## Как работает

### Учет дат создания и деактивации объектов

При создании снимка на конкретную дату (например, 15 ноября 2025):

1. **Дата создания**: Объект учитывается, только если был создан до или в день снимка
   - Объект создан 10 ноября → учитывается ✅
   - Объект создан 20 ноября → НЕ учитывается ❌

2. **Дата удаления**: Объект учитывается, только если не был удален до даты снимка
   - Объект удален 20 ноября → учитывается ✅
   - Объект удален 10 ноября → НЕ учитывается ❌

3. **Статус активности**: Используется текущий статус `isActive` из Axenta Cloud API

### Формула расчета стоимости

Формула осталась прежней:
- **Дневная цена** = Месячный тариф ÷ 30 дней (округляется до 4 знаков)
- **Стоимость за день** = Дневная цена × Количество активных объектов (округляется до копеек)
- **Общая стоимость** = Сумма всех дневных стоимостей за период

## Инструкция по использованию

### Для пользователя

1. Откройте раздел "Биллинг" → вкладка "Договоры"
2. Найдите партнерский договор в списке
3. Нажмите на иконку калькулятора (📊) для просмотра статистики
4. В открывшемся диалоге:
   - Выберите период с помощью date pickers
   - Нажмите "Применить" для загрузки статистики
   - Если снимков нет, нажмите "Создать снимки" (может занять время для больших периодов)
5. Просмотрите ежедневные снимки и общую сводку

### Для разработчика

#### Создание снимков через API:

```bash
# Создать снимки за период для договора с ID=35
curl -X POST http://localhost:8080/api/auth/contracts/35/partner-snapshots/generate \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "X-Tenant-ID: YOUR_TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "start_date": "2025-11-01",
    "end_date": "2025-11-30"
  }'
```

#### Получение снимков за период:

```bash
# Получить снимки за ноябрь 2025
curl http://localhost:8080/api/auth/contracts/35/partner-snapshots?start_date=2025-11-01T00:00:00Z&end_date=2025-11-30T23:59:59Z \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "X-Tenant-ID: YOUR_TENANT_ID"
```

## Технические детали

### Обработка дат из Axenta Cloud API

Поддерживаются следующие форматы дат:
- RFC3339: `2025-11-15T12:00:00+03:00`
- ISO 8601: `2025-11-15T12:00:00.000Z`
- ISO 8601 без миллисекунд: `2025-11-15T12:00:00Z`
- SQL формат: `2025-11-15 12:00:00`
- Только дата: `2025-11-15`

### Производительность

- Снимки создаются последовательно для каждого дня
- Для периода в 30 дней создание займет ~30-60 секунд (в зависимости от количества объектов)
- Рекомендуется создавать снимки заранее или в фоновом режиме для больших периодов

### Безопасность

- Все запросы требуют авторизации
- Фильтрация по `admin_account_id` для изоляции данных компаний [[memory:11460401]]
- Используется токен пользователя для запросов к Axenta Cloud API

## Тестирование

### Сценарии тестирования

1. **Создание снимков за прошлый период**:
   - Выбрать период (например, последний месяц)
   - Создать снимки
   - Проверить, что все снимки созданы корректно

2. **Просмотр статистики за разные периоды**:
   - Выбрать период 1 (например, первая неделя месяца)
   - Проверить статистику
   - Выбрать период 2 (например, весь месяц)
   - Проверить, что статистика обновилась

3. **Обновление существующих снимков**:
   - Создать снимки за период
   - Создать снимки за тот же период повторно
   - Проверить, что данные обновились (а не дублировались)

### Проверка учета дат

Для проверки правильности учета дат создания/удаления объектов:
1. Найдите объект с известной датой создания в Axenta Cloud
2. Создайте снимок на дату до создания объекта
3. Создайте снимок на дату после создания объекта
4. Проверьте, что количество объектов отличается

## Известные ограничения

1. **Статус активности**: Используется текущий статус `isActive` из API, а не исторический. Если объект был активен в прошлом, но сейчас неактивен, он будет учитываться как неактивный для всех дат.

2. **История изменений**: Axenta Cloud API не предоставляет полную историю изменений статусов объектов, поэтому мы используем только даты создания и удаления.

3. **Производительность**: Для больших периодов (>30 дней) создание снимков может занять значительное время.
