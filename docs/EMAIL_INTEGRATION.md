# Email SMTP Интеграция в Axenta CRM

## Обзор

Email SMTP интеграция позволяет отправлять уведомления пользователям через электронную почту. Система поддерживает все популярные почтовые провайдеры (Gmail, Mail.ru, Yandex, Office365 и др.) с настройкой SMTP подключения.

## Настройка Email SMTP

### Шаг 1: Выбор SMTP провайдера

Выберите одного из популярных провайдеров:

#### Gmail
- **SMTP Сервер:** `smtp.gmail.com`
- **Порт:** `587` (TLS) или `465` (SSL)
- **Требования:** Необходимо создать App Password
- **Инструкция:** https://support.google.com/accounts/answer/185833

#### Mail.ru
- **SMTP Сервер:** `smtp.mail.ru`
- **Порт:** `587` (TLS) или `465` (SSL)
- **Логин:** Полный email адрес
- **Пароль:** Обычный пароль от аккаунта

#### Yandex
- **SMTP Сервер:** `smtp.yandex.ru`
- **Порт:** `587` (TLS) или `465` (SSL)
- **Логин:** Полный email адрес
- **Требования:** Может потребоваться App Password

#### Microsoft Office 365
- **SMTP Сервер:** `smtp.office365.com`
- **Порт:** `587` (TLS)
- **Логин:** Полный email адрес
- **Пароль:** Пароль от аккаунта

### Шаг 2: Настройка в Axenta CRM

1. Откройте **Настройки** → **Интеграции**
2. Найдите карточку **Email SMTP**
3. Нажмите **Настроить**
4. Заполните форму:
   - **SMTP сервер** - адрес SMTP сервера (например, smtp.gmail.com)
   - **Порт** - порт SMTP (обычно 587 для TLS или 465 для SSL)
   - **Имя пользователя** - ваш email адрес
   - **Пароль** - пароль или App Password
   - **Email отправителя** - email, с которого будут отправляться письма
   - **Имя отправителя** - отображаемое имя отправителя (например, "Axenta CRM")
   - **Использовать TLS/SSL** - рекомендуется включить
5. Нажмите **Тестировать подключение**
6. Если тест прошел успешно, нажмите **Сохранить**

### Шаг 3: Создание App Password для Gmail

Если вы используете Gmail с двухфакторной аутентификацией:

1. Перейдите в настройки Google Account: https://myaccount.google.com/
2. Выберите **Security** (Безопасность)
3. Найдите раздел **2-Step Verification** (Двухэтапная аутентификация)
4. Найдите **App passwords** (Пароли приложений)
5. Создайте новый пароль приложения для "Mail"
6. Скопируйте сгенерированный пароль (без пробелов)
7. Используйте этот пароль вместо обычного пароля в настройках Email SMTP

## API Методы

### 1. Настройка Email интеграции (POST)

**Endpoint:** `POST /api/email/setup`

**Требуется авторизация:** Да (Администратор)

**Тело запроса:**
```json
{
  "smtp_host": "smtp.gmail.com",
  "smtp_port": 587,
  "smtp_username": "your-email@gmail.com",
  "smtp_password": "your-app-password",
  "smtp_from_email": "noreply@company.com",
  "smtp_from_name": "Axenta CRM",
  "smtp_use_tls": true
}
```

**Ответ:**
```json
{
  "status": "success",
  "message": "Настройки Email SMTP успешно сохранены",
  "config": {
    "smtp_host": "smtp.gmail.com",
    "smtp_port": 587,
    "smtp_username": "your-email@gmail.com",
    "smtp_from_email": "noreply@company.com",
    "smtp_from_name": "Axenta CRM",
    "smtp_use_tls": true,
    "enabled": true,
    "is_active": true
  }
}
```

### 2. Обновление Email интеграции (PUT)

**Endpoint:** `PUT /api/email/setup`

**Требуется авторизация:** Да (Администратор)

**Тело запроса:** Аналогично POST запросу

**Ответ:** Аналогично POST запросу

### 3. Получение конфигурации Email (GET)

**Endpoint:** `GET /api/email/config`

**Требуется авторизация:** Да

**Ответ:**
```json
{
  "status": "success",
  "config": {
    "smtp_host": "smtp.gmail.com",
    "smtp_port": 587,
    "smtp_username": "your-email@gmail.com",
    "smtp_password": "*********************",
    "smtp_from_email": "noreply@company.com",
    "smtp_from_name": "Axenta CRM",
    "smtp_use_tls": true,
    "enabled": true,
    "is_active": true
  }
}
```

**Примечание:** Пароль маскируется в ответе из соображений безопасности.

### 4. Тестирование подключения (POST)

**Endpoint:** `POST /api/email/test-connection`

**Требуется авторизация:** Да

**Описание:** Отправляет тестовое письмо на email текущего пользователя

**Ответ (успешно):**
```json
{
  "status": "success",
  "message": "Тестовое письмо успешно отправлено на user@example.com"
}
```

**Ответ (ошибка):**
```json
{
  "status": "error",
  "error": "Ошибка отправки тестового письма",
  "details": "535 5.7.8 Username and Password not accepted"
}
```

## Формат Email уведомлений

### Структура письма

Все письма отправляются в формате:

```
From: [smtp_from_name] <[smtp_from_email]>
To: [user_email]
Subject: [Тема уведомления]
Content-Type: text/plain; charset=UTF-8

[Тело письма]

---
С уважением,
Команда Axenta CRM
```

### Типы уведомлений

Email используется для следующих типов уведомлений:

1. **Биллинг и счета**
   - Создание нового счета
   - Напоминание об оплате
   - Подтверждение оплаты
   - Просроченная оплата

2. **Установки и объекты**
   - Напоминания о предстоящих установках
   - Изменение статуса установки
   - Назначение на объект

3. **Складские операции**
   - Критически низкий остаток на складе
   - Поступление товаров
   - Списание оборудования

4. **Системные уведомления**
   - Сброс пароля
   - Изменение настроек аккаунта
   - Важные системные обновления

## Настройка пользовательских предпочтений

Каждый пользователь может настроить, какие уведомления он хочет получать по Email:

1. Откройте **Настройки** → **Уведомления**
2. Найдите канал **Email**
3. Включите/отключите категории уведомлений:
   - Напоминания об установках
   - Обновления установок
   - Биллинг и счета
   - Складские уведомления
   - Системные уведомления

## Безопасность

### Хранение паролей

- SMTP пароли хранятся в зашифрованном виде в базе данных
- При получении конфигурации через API, пароль маскируется
- Доступ к настройкам Email имеют только администраторы

### Рекомендации

1. **Используйте App Password** вместо основного пароля (особенно для Gmail)
2. **Включайте TLS/SSL** для безопасной передачи данных
3. **Создайте отдельный email** для отправки уведомлений (например, noreply@company.com)
4. **Настройте SPF/DKIM** записи для вашего домена для улучшения доставляемости

## Troubleshooting (Решение проблем)

### Ошибка: "Username and Password not accepted"

**Причина:** Неверные учетные данные или Gmail блокирует вход.

**Решение:**
1. Проверьте правильность email и пароля
2. Для Gmail создайте App Password
3. Проверьте, не заблокирован ли вход в аккаунт

### Ошибка: "Connection timeout"

**Причина:** Неверный SMTP сервер или порт, или сеть блокирует подключение.

**Решение:**
1. Проверьте правильность SMTP сервера и порта
2. Убедитесь, что фаервол не блокирует исходящие подключения на порт 587/465
3. Проверьте настройки TLS/SSL

### Ошибка: "TLS handshake failed"

**Причина:** Проблемы с SSL/TLS подключением.

**Решение:**
1. Попробуйте переключиться между портами 587 и 465
2. Проверьте настройку "Использовать TLS/SSL"
3. Обновите сертификаты SSL на сервере

### Письма не доходят (попадают в спам)

**Причина:** Отсутствие правильной настройки DNS записей.

**Решение:**
1. Настройте SPF запись для вашего домена:
   ```
   v=spf1 include:_spf.google.com ~all
   ```
2. Настройте DKIM подпись
3. Добавьте DMARC политику
4. Используйте профессиональный email домен вместо публичных сервисов

### Тестовое письмо не приходит

**Причина:** Различные возможные причины.

**Решение:**
1. Проверьте папку спам
2. Убедитесь, что email пользователя указан правильно
3. Проверьте логи сервера на наличие ошибок
4. Попробуйте отправить тестовое письмо на другой email

## Ограничения провайдеров

### Gmail
- **Лимит:** ~500 писем в день для бесплатных аккаунтов
- **Рекомендация:** Используйте Google Workspace для больших объемов

### Mail.ru
- **Лимит:** ~300 писем в день для бесплатных аккаунтов
- **Рекомендация:** Используйте Mail.ru для бизнеса для больших объемов

### Yandex
- **Лимит:** ~500 писем в день
- **Рекомендация:** Используйте Yandex.Connect для бизнеса

### Office 365
- **Лимит:** ~300 писем в день для E1/E3 планов
- **Рекомендация:** Используйте Exchange Online Plan 2 для больших объемов

## Мониторинг и логи

Система автоматически логирует все попытки отправки Email:

- **Успешные отправки:** Записываются в таблицу `notification_logs`
- **Ошибки отправки:** Логируются с деталями ошибки
- **Статистика:** Доступна в разделе Настройки → Уведомления → Логи
