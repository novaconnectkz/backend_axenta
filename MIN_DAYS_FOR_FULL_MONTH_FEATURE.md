# Настройка минимального количества дней для начисления полного месяца

## Описание
Добавлена возможность контролировать количество дней присутствия объекта в подписке в месяц. Если объект присутствует более указанного количества дней в системе, то начисляется и списывается полный месяц.

## Настройка по умолчанию
**5 дней** - значение по умолчанию. Если объект присутствует в системе 5 или более дней в месяце, то списывается стоимость полного месяца.

## Что изменено

### Backend

#### 1. Модель данных (`models/invoice.go`)
Добавлено новое поле в структуру `BillingSettings`:
```go
MinDaysForFullMonth int `json:"min_days_for_full_month" gorm:"default:5"`
```

#### 2. Миграция БД (`database/migrations.go`)
Добавлена автоматическая миграция для создания колонки `min_days_for_full_month` в таблице `billing_settings`:
```go
{"billing_settings", "min_days_for_full_month", "INTEGER DEFAULT 5", false}
```

#### 3. Логика расчёта биллинга (`services/billing_advanced.go`)
Обновлена функция `calculateObjectBilling()`:
- Получает настройку `MinDaysForFullMonth` из `BillingSettings`
- Для месячных тарифов (`BillingPeriod == "monthly"`):
  - Если `billableDays >= MinDaysForFullMonth` → списывается полная месячная стоимость
  - Если `billableDays < MinDaysForFullMonth` → списывается пропорционально дням
- Добавлены дополнительные поля в результат расчёта:
  - `charged_as_full_month` - был ли списан полный месяц
  - `min_days_for_full_month` - используемое значение настройки

#### 4. API схема (`configs/billing-openapi.yaml`)
Добавлено поле в схемы:
- `BillingSettings` - для чтения настроек
- `BillingSettingsUpdate` - для обновления настроек

Параметры:
- Тип: `integer`
- Минимум: 1
- Максимум: 31
- По умолчанию: 5

#### 5. Упрощённый API (`api/billing_simple.go`)
Добавлено поле `min_days_for_full_month: 5` в демо-данные настроек биллинга.

#### 6. Сервис биллинга (`services/billing_service.go`)
При создании настроек биллинга по умолчанию устанавливается `MinDaysForFullMonth: 5`.

### Frontend

#### 1. TypeScript типы (`src/types/billing.ts`)
Добавлено поле в интерфейс `BillingSettings`:
```typescript
min_days_for_full_month: number;
```

#### 2. UI компонент настроек биллинга (`src/views/Billing.vue`)

**Добавлена новая секция "Тарификация объектов":**
- Поле ввода числа: "Мин. дней для полного месяца" (диапазон: 1-31)
- Постоянная подсказка под полем: объясняет логику работы настройки
- Иконка информации (ℹ️) справа от поля: при наведении показывает всплывающую подсказку с примерами расчёта

**Автосохранение:**
- Добавлен универсальный watch с `deep: true` для всех полей настроек биллинга
- Специальные watch для отдельных полей: `contract_numbering_method`, `min_days_for_full_month`
- Сохранение происходит с задержкой 500ms после последнего изменения любого поля
- Индикатор состояния сохранения (сохранение/несохранённые изменения/сохранено)
- Работает для всех полей формы:
  - Генерация счетов: день месяца, срок оплаты, автоматическая генерация
  - Уведомления: до выставления счета, до срока оплаты, после просрочки
  - Льготные тарифы: коэффициент льготы, переключатели
  - Тарификация объектов: минимальное количество дней

**Инициализация:**
- При загрузке настроек, если поле не задано, автоматически устанавливается значение 5
- Значение синхронизируется с backend при каждом сохранении

**Расположение в UI:**
Биллинг → Вкладка "Настройки" → Секция "Тарификация объектов" (внизу формы настроек)

## Примеры использования

### Пример 1: Объект присутствует 7 дней
- Настройка: `min_days_for_full_month = 5`
- Присутствие: 7 дней
- Результат: **Списывается полная месячная стоимость**

### Пример 2: Объект присутствует 3 дня
- Настройка: `min_days_for_full_month = 5`
- Присутствие: 3 дня
- Результат: **Списывается пропорционально (3/30 от месячной стоимости)**

### Пример 3: Объект присутствует ровно 5 дней
- Настройка: `min_days_for_full_month = 5`
- Присутствие: 5 дней
- Результат: **Списывается полная месячная стоимость** (граничное значение включительно)

## Миграция БД
При следующем запуске миграций автоматически будет добавлена колонка `min_days_for_full_month` со значением по умолчанию 5 для всех существующих записей в таблице `billing_settings`.

## API эндпоинты
Настройка доступна через стандартные эндпоинты биллинга:
- `GET /api/billing/settings` - получение настроек (включая `min_days_for_full_month`)
- `PUT /api/billing/settings` - обновление настроек (можно изменить `min_days_for_full_month`)

## Изоляция по компаниям
Настройка `min_days_for_full_month` изолирована по `company_id`, как и все остальные настройки биллинга. Каждая компания может иметь своё значение этой настройки.

## Обратная совместимость
- Для существующих компаний без настроек биллинга при первом обращении будут созданы настройки с `min_days_for_full_month = 5`
- Для компаний с существующими настройками после миграции будет добавлено значение по умолчанию 5
- Логика расчёта не изменяется для годовых и других типов тарифов - только для месячных (`monthly`)
