# Исправление проблем с миграциями и схемами БД

## 🚨 Обнаруженные проблемы

### 1. Неполная система миграций
- **Проблема**: LocalUser и RefreshToken не были включены в систему автоматических миграций
- **Симптом**: Таблицы `local_users` и `refresh_tokens` могли не создаваться при запуске
- **Причина**: В `main.go` была отдельная миграция, не интегрированная с `RunAllMigrations()`

### 2. Несоответствие схем БД
- **Проблема**: LocalUser и RefreshToken могли искаться в неправильной схеме
- **Симптом**: Ошибки "table does not exist" при работе с локальной авторизацией
- **Причина**: Отсутствие явного переключения на схему `public` для глобальных таблиц

### 3. Конфликт между мультитенантностью и глобальными таблицами
- **Проблема**: Middleware мог переключать схему, влияя на поиск глобальных таблиц
- **Симптом**: Непредсказуемые ошибки в зависимости от порядка запросов
- **Причина**: Отсутствие изоляции между tenant-специфичными и глобальными операциями

**Файл**: `api/local_auth.go`
- ✅ Добавлен метод `getPublicDB()` для явного переключения на схему `public`
- ✅ Все операции с LocalUser теперь используют `publicDB`
- ✅ Гарантирована работа в правильной схеме независимо от контекста

```go
// Новый метод для изоляции схемы
func (api *LocalAuthAPI) getPublicDB() *gorm.DB {
    publicDB := api.db.Session(&gorm.Session{})
    if err := publicDB.Exec("SET search_path TO public").Error; err != nil {
        log.Printf("⚠️ Не удалось переключиться на схему public: %v", err)
    }
    return publicDB
}
```
