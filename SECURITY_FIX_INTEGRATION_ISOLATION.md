# Исправление критической уязвимости изоляции данных интеграций

## Дата: 22.11.2025

## Проблема

Обнаружена **критическая уязвимость безопасности** в файле `api/email.go`, которая позволяла видеть настройки Email SMTP одной компании пользователям другой компании.

### Корневая причина

В файле `api/email.go` были следующие проблемы:

1. **Неправильное получение `company_id`**:
   ```go
   // БЫЛО (НЕПРАВИЛЬНО):
   companyID, exists := c.Get("company_id")
   if !exists {
       companyID = uint(186) // fallback для совместимости
   }
   ```
   - Использовался `c.Get("company_id")` вместо `middleware.GetCompanyID(c)`
   - Был опасный fallback на hardcoded значение `uint(186)`
   - Если company_id не был найден, все пользователи получали доступ к данным компании с ID 186

2. **Правильное, но недостаточно защищенное использование БД**:
   ```go
   database.DB.Table("public.notification_settings").Where("company_id = ?", companyID)
   ```
   - Хотя фильтрация по `company_id` была, но из-за fallback на 186 это не работало корректно

### Затронутые функции

- `SetupEmailIntegration()` - настройка Email SMTP
- `GetEmailConfig()` - получение конфигурации Email SMTP
- `TestEmailConnection()` - тестирование подключения Email SMTP

## Решение

### Внесенные изменения

1. **Добавлен импорт middleware**:
   ```go
   import (
       "backend_axenta/middleware"
       // ...
   )
   ```

2. **Исправлено получение company_id во всех функциях**:
   ```go
   // СТАЛО (ПРАВИЛЬНО):
   companyID := middleware.GetCompanyID(c)
   if companyID == 0 {
       c.JSON(http.StatusBadRequest, gin.H{
           "status": "error",
           "error":  "Не удалось определить компанию. Обратитесь к администратору.",
       })
       return
   }
   ```

3. **Добавлены комментарии безопасности**:
   ```go
   // КРИТИЧНО: Получаем company_id из контекста через middleware
   // КРИТИЧНО: Используем прямой SQL запрос с явным указанием схемы public и фильтрацией по company_id
   ```

- `api/email.go` - исправлено ✅

## Принцип изоляции данных

### Правильный подход для всех будущих интеграций

```go
// 1. Получаем company_id из middleware
companyID := middleware.GetCompanyID(c)

// 2. ВСЕГДА проверяем, что company_id получен
if companyID == 0 {
    c.JSON(http.StatusBadRequest, gin.H{
        "error": "Не удалось определить компанию",
    })
    return
}

// 3. Фильтруем ВСЕ запросы по company_id
db.Where("company_id = ?", companyID).Find(&records)
```

### Недопустимые практики

❌ **НИКОГДА не используйте**:
```go
// ПЛОХО: fallback на hardcoded значение
companyID, exists := c.Get("company_id")
if !exists {
    companyID = uint(186) // ← ОПАСНО!
}

// ПЛОХО: fallback на любое значение по умолчанию
companyID := getCompanyID(c)
if companyID == 0 {
    companyID = 1 // ← ОПАСНО!
}

// ПЛОХО: запросы без фильтрации по company_id
db.Find(&records) // ← вернет данные ВСЕХ компаний!
```

✅ **ВСЕГДА используйте**:
```go
// ХОРОШО: строгая проверка company_id
companyID := middleware.GetCompanyID(c)
if companyID == 0 {
    return error // или c.AbortWithError()
}

// ХОРОШО: обязательная фильтрация по company_id
db.Where("company_id = ?", companyID).Find(&records)
```

## Создана память

Создана память (ID: 11460401) с критически важным правилом:
> Все настройки интеграций и данные должны быть строго изолированы по company_id. Каждая компания должна видеть только свои собственные настройки и данные. При создании, чтении, обновлении и удалении любых данных ВСЕГДА фильтровать по company_id текущего пользователя.
